# Personal MAX text sender v1

This directory contains the fail-closed text-sender contract, its offline synthetic adapter, and the durable physical canary boundary used by `max-web-scraper/index.js`. The physical boundary is exposed only at the private `/v1/personal-max/send/text` route and is absent unless `MAX_PERSONAL_TEXT_SENDER_ENABLED=true` has a complete exact binding.

The in-memory replay and idempotency stores remain test-only. The physical runtime uses fsync-backed replay, idempotency, attempt, post-action uncertainty, daily-limit, and safety-stop evidence under a persistent `/var/lib/...` mount. A reserved pre-action attempt can be recovered after process restart; an attempt durably marked as physically started is never blindly retried. Authentication uses the dedicated `personal-max-sender-v1` namespace and does not reuse capture credentials. The scraper asks the gateway to recheck the exact route, immutable command/attempt, and current SessionOwner fencing immediately before the provider action.

All physical gates are disabled by default and require exact account and single-conversation allowlists, an explicit emergency-stop clear, and a daily limit. The provider adapter sends only the native MAX `SEND_MESSAGE` frame, permits text only, forbids reply/reaction/media and fallback routing, and reports confirmation only when MAX returns an exact provider message ID. It never reports recipient delivery. The synthetic adapter records identities in a test ledger and permanently reports zero physical provider calls.
