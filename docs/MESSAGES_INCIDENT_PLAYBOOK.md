# Messages Incident Playbook

## Сообщение не появилось

1. Не отправляйте повторное сообщение автоматически.
2. Сохраните канал, Contact/Chat ID, provider message ID, время и направление.
3. Проверьте, есть ли событие в provider contract logs и в CRM timeline.
4. Проверьте, не открыт ли provider-only Contact вместо canonical карточки.
5. Для MAX проверьте pipeline по `MAX_MESSAGE_FORENSIC.md`; не редактируйте
   scraper и не запускайте массовую повторную обработку без отдельного решения.

## Канал показывает «нет связи»

Это техническое состояние CRM: повторите проверку после восстановления
сессии. Не сообщайте человеку, что у него нет мессенджера, и не меняйте его
карточку.

## Яндекс отвечает ограничением

Панель должна показать последнюю сохранённую информацию и компактное
сообщение. Дождитесь доступного backoff и используйте «Повторить» только
после его завершения. Не меняйте статус работы, главный профиль и не
открепляйте профиль из-за `429` или timeout.

## Подозрение на ошибочную связь

Остановите автоматическое действие, зафиксируйте номер и обе карточки.
Проверьте ownership. Для ambiguous случая требуется ручная проверка; merge
или перенос профиля выполняется только через явное подтверждение.
