# Contact Resolution Operations

## Обычная работа оператора

- Ищите сначала по телефону, затем по ФИО, username или внешнему ID профиля.
- Открывайте canonical Contact, а не provider-only дубль.
- Добавляйте номер только через диалог предварительной проверки.
- Проверяйте предложения профилей и подтверждайте только профили одного
  человека.
- Назначайте главный профиль только из активных уже прикреплённых профилей.

## Состояния номера

`Свободен` позволяет продолжить добавление. `Уже у этого контакта` не создаёт
дубль. `У другого контакта` и `Несколько владельцев` останавливают запись:
нужна ручная проверка карточек, а не перенос номера.

## Обновление профилей

Открытие карточки немедленно показывает сохранённые данные и принимает
решение, нужно ли обновление. Внешний запрос выполняется только для устаревших
данных или после доступной кнопки «Повторить». Одинаковые запросы к одному
парку объединяются. При ограничении Яндекса показана последняя сохранённая
информация; статус работы и главный профиль не изменяются.

## Каналы

Цвет и подпись у MAX, Telegram и WhatsApp описывают только доступность
аккаунта: `есть`, `нет`, `проверяем`, `нет связи`. Наличие строки канала либо
чата в CRM не доказывает наличие аккаунта. `Нет связи` означает техническую
недоступность проверки CRM, а не отсутствие аккаунта у человека.

## Инциденты

Не исправляйте проблему повторной отправкой, merge или удалением Contact.
Зафиксируйте Contact ID, канал, provider message ID, время и текст ошибки,
затем используйте playbook `MESSAGES_INCIDENT_PLAYBOOK.md`.
