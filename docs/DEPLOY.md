# Деплой CRM на Beget VPS — гайд для человека

Этот документ — твой пошаговый путеводитель по переезду CRM с локальной машины
на сервер. Написан простым языком, без жаргона. Если что-то непонятно — лучше
остановись и переспроси, чем сделать наугад.

> **Важно:** этот гайд описывает только **что и в каком порядке** делать.
> Конкретные команды и скрипты лежат в `scripts/` и в `deploy/`. Сами
> секреты (пароли, токены) — в твоём пасс-менеджере, никогда не в репозитории.

---

## 1. Что мы переносим и куда

**Откуда:** Windows + локальные процессы (npm run dev в нескольких терминалах).

**Куда:** Beget VPS — 4 vCPU / 8 GB RAM / 80 GB SSD, Ubuntu 22.04 LTS.

**Что едет на VPS:**

| Слой | Где живёт | Почему именно так |
|------|-----------|-------------------|
| Postgres | Docker | Версия фиксирована, изоляция, удобные бэкапы |
| Redis | Docker | Очередь задач для скрапера |
| nginx | Docker | Единая входная точка HTTPS |
| gravity-mvp (CRM) | Docker (этап 2) | Next.js приложение, порт 3002 внутри |
| tg-bot + frontend | Docker (этап 2) | Telegram-бот водителей и его админка |
| yandex-fleet-scraper API + worker | Docker (этап 2) | API и Playwright-воркер |
| max-web-scraper | Docker (этап 2) | Скрапер мессенджера MAX |
| **FreeSWITCH** | **Хост, НЕ Docker** | UDP/RTP голос плохо ходит через Docker NAT |
| **coturn** | **Хост, НЕ Docker** | То же самое — голосовой трафик |
| **xray (SOCKS5 для Claude API)** | **Хост, НЕ Docker** | Меньше сетевых прыжков, надёжнее |

**Что НЕ едет:**
- AI-инференс (Whisper, LLM веса) — никогда на этом VPS, только внешние API.
- Avito-парсер — выключен по решению (экономим ресурсы).

**Бэкапы:** уходят в **Selectel Object Storage** (S3-совместимое хранилище):
- Postgres — ежедневно, retention `14 daily + 4 weekly + 6 monthly`.
- Профили браузера для скрапера — ежедневно.
- `.env` и конфиги — после каждого изменения, зашифрованы через **age**.
- Аудио-записи звонков — **write-through** (пишутся сразу, не ждут ночи).

**Алерты:** в личку через `@yoko_park_bot` (когда падает что-то критичное).

**Время восстановления при инциденте:** **1–3 часа по playbook**. Не "за час".
Закладываем спокойно, без героизма.

## 2. Чего НЕ делать на VPS

| Не делать | Почему |
|-----------|--------|
| Не ставить Postgres вне Docker | Усложняет бэкапы и версионирование |
| Не запускать `docker-compose up` без `.env.production` | Compose падает с ошибкой про обязательные переменные — и правильно делает |
| Не хранить приватный age-ключ на сервере | Если сервер взломают — секреты прочитают. Ключ только у тебя в пасс-менеджере |
| Не открывать порт Postgres наружу (5432) | Доступ только через внутреннюю Docker-сеть |
| Не редактировать файлы прямо на сервере "по-быстрому" | Пушим через git → пересобираем образ |
| Не отключать swap | 6 GB swap обязателен, без него Playwright и Next.js билды падают по OOM |

## 3. Первичная установка сервера (один раз)

Делается один раз при покупке VPS.

**Шаг 1. Получить доступ к VPS.**
- Купить VPS на Beget (4 vCPU / 8 GB RAM / 80 GB SSD, Ubuntu 22.04).
- Записать IP-адрес и root-пароль.
- Подключиться по SSH: `ssh root@<IP>`.

**Шаг 2. Запустить setup-server.sh.**
- Скрипт лежит в `scripts/setup-server.sh`.
- Что делает (подробности — в самом скрипте, в комментариях):
  - Создаёт пользователя `crm` (работаем не из-под root).
  - Включает 6 GB swap-файл.
  - Ставит Docker + docker-compose-plugin.
  - Ставит FreeSWITCH, coturn, xray на **хост** (не в Docker).
  - Ставит `age` (для шифрования секретов) и `rclone` (для отправки бэкапов в S3).
  - Настраивает базовый firewall (открыты только 22, 80, 443, плюс SIP/RTP-порты).
- Запуск: `bash scripts/setup-server.sh`. Скрипт логирует каждый шаг.

**Шаг 3. Подготовить секреты.**
- См. отдельный документ `docs/SECRETS.md` — там полный список того,
  что должно быть в `.env.production`, и как его зашифровать через age.

**Шаг 4. Поднять базовый стек (Postgres + Redis + nginx).**
- На VPS: `cd /opt/crm && docker compose -f deploy/docker-compose.production.yml up -d postgres redis nginx`.
- Проверить `docker ps` — должны быть 3 контейнера в статусе `healthy`.

**Шаг 5. Настроить домен и HTTPS.**
- Когда выберешь домен — направить A-запись на IP VPS.
- nginx-конфиг (будет добавлен в этапе 2) сам получит сертификат Let's Encrypt.

## 4. Каждый деплой нового кода

После первичной установки. Делается, когда хочешь выкатить изменения.

```
Локально:  git push → ветка main
   ↓
На VPS:    git pull → docker compose build → docker compose up -d
```

Подробный пошаговый скрипт деплоя оформим в `scripts/deploy.sh` на этапе 2
(вместе с упаковкой сервисов в Dockerfile).

## 5. Бэкапы — что и когда

| Что | Когда | Скрипт | Куда |
|-----|-------|--------|------|
| Postgres dump | Каждый день в 03:00 | `scripts/backup-pg.sh` | S3 `pg/` |
| Профили браузера скрапера | Каждый день в 03:30 | `scripts/backup-files.sh` | S3 `files/` |
| `.env` и конфиги (age-шифр) | После каждого изменения | `scripts/backup-env.sh` | S3 `env/` |
| Аудио звонков | Сразу при записи (write-through) | внутри tg-bot/freeswitch | S3 `calls/` |

**Retention** (сколько копий храним):
- 14 daily — последние 14 дней.
- 4 weekly — по одной на 4 предыдущие недели.
- 6 monthly — по одной на 6 предыдущих месяцев.
- Старее — автоудаление через lifecycle policy S3.

**Восстановление из бэкапа** — см. `scripts/restore-pg.sh` и
`scripts/restore-test.sh` (последний — ежемесячно тестируем что бэкап рабочий,
без этого "бэкапы есть" = "бэкапов нет").

## 6. Мониторинг и алерты

Скрипт `scripts/health-monitor.sh` запускается раз в минуту через cron.

**Что проверяет:**
- Все контейнеры в статусе `healthy`.
- Свободное место на диске > 10 GB.
- Postgres отвечает на `pg_isready`.
- FreeSWITCH/coturn (на хосте) — отвечают.
- Последний бэкап в S3 — не старше 26 часов.

**Если что-то не так** — алерт в `@yoko_park_bot` в твою личку.
**Если всё ок** — молчит.

## 8. Что читать, когда что-то идёт не так

| Ситуация | Куда смотреть |
|----------|---------------|
| Не понимаю что в каком файле | Этот документ, раздел 1 |
| Как зашифровать новый секрет | `docs/SECRETS.md` |
| Сервер не отвечает | SSH → `docker ps` → логи проблемного контейнера |
| Нужно восстановить базу | `scripts/restore-pg.sh` |
| Бэкап вообще делается? | Логи `scripts/health-monitor.sh`, S3-консоль Selectel |
| Звонки не идут | FreeSWITCH живёт на хосте, не в Docker — `systemctl status freeswitch` |
