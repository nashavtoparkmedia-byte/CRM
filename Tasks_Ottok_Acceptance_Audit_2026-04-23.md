## Слой 4 — Excel-контракт

- 3 листа: `Как_пользоваться`, `Отток_шаблон`, `Справочники`
- 23 колонки A–W, headers в row 3
- 6 merged-ячеек в row 2 (цветные блочные шапки): `A2:C2 Идентификация #F3F4F6`, `D2:F2 Управление кейсом #EDE9FE`, `G2:I2 Контекст водителя #EAF2FF`, `J2:O2 Работа менеджера #FFF4CC`, `P2:S2 Оффер и правила #E8F5E9`, `T2:W2 Закрытие #FDECEA`

### Топ-5 критичных расхождений

1. **V1/V2/V3 — нет цветных блочных шапок над колонками** (P0). Это ключевое требование «Таблица должна визуально напоминать Excel». Сейчас нет ни двухрядного хедера, ни 6 цветов (`#F3F4F6 / #EDE9FE / #EAF2FF / #FFF4CC / #E8F5E9 / #FDECEA`). 5. **V4 + D1 — заголовки колонок не дословно совпадают с xlsx + сырое `true/false` в колонке «Катает в Яндекс»** (P1). «ФИО водителя» → «ФИО», «Дедлайн следующего действия» → «Дедлайн», отсутствует колонка «Что написать водителю (готовый текст)» и «Итог закрытия» в Таблице. `yandexActive` булево рендерится как строка `true`/`false` вместо «да»/«нет».

## Две ревизионные заметки для исполнителя

1. **Внутреннее несоответствие эталонов А и C.** В исходном ТЗ написано два разных набора блоков:
   - Эталон A: 6 блоков — Идентификация / Управление кейсом / Контекст водителя / Последний контакт / Следующее действие / Управление возвратом.
   - Эталон C (xlsx): 6 блоков — Идентификация / Управление кейсом / Контекст водителя / Работа менеджера / Оффер и правила / Закрытие.

   Сейчас UI матчит A (popup «Настроить колонки»), а Excel-экспорт матчит C. Пока расхождение не фиксят — экспорт и UI показывают разные группировки одних и тех же полей. Нужно решение: либо привести UI к xlsx-схеме, либо поменять xlsx-шаблон под A (менее болезненно для пользователей).

2. **Операционный ≠ Таблица.** Операционный режим — карточки с микро-лейблами, хорошо для «проактивной работы». Таблица должна быть отдельно-визуально плотным Excel-видом с 2-ряд хедером и цветами. Сейчас Таблица по сути — та же карточная лента, просто с добавленным верхним одноуровневым хедером. V1–V5 провалены именно из-за того, что Таблица-вид не построен как настоящий DataGrid.
