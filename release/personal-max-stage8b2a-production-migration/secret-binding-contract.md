# Production database secret binding

The PostgreSQL container is the only authority for production database credentials. The future root script discovers exactly one container carrying Compose project label `crm` and service label `postgres`, requires it to be running with the accepted image ID, writes one complete `docker inspect` document to a no-clobber `root:root:0600` file, and never prints that document.

The hard-bound Python helper accepts only the inspect-file and output-file paths in `argv`. It requires exactly one non-empty occurrence of each of `POSTGRES_USER`, `POSTGRES_PASSWORD`, and `POSTGRES_DB`; rejects duplicates and control characters; percent-encodes every credential URL component; fixes the URL host, port, and schema to `postgres`, `5432`, and `public`; and atomically creates a no-clobber `root:root:0600` env file. Credentials never appear in command arguments, reports, logs, or terminal output.

The inspected PostgreSQL container must have exactly one eligible network. That network must carry Compose project label `crm` and Compose network label `internal`, and the container must have alias `postgres`. Each deterministic disposable Prisma runner receives exactly that network, no public ports, no host/default network, and the root-only env file. Container ID, running state, and image identity are fenced before and after each sensitive phase. The bounded EXIT cleanup removes the credential workspace only when its exact path, ownership, type, and `0700` mode match the package policy.
