1. Architect accepts the exact isolated, migration, dormant-rollout, and scraper-default-off evidence before authorizing only one bounded target/window.
2. Verify the root-owned observer snapshot checksum, accepted migration legacy-drift status, current database schema/ledger contract, exact actual gateway/scraper repo digests, OCI source revisions, container start times, Docker health, gateway topology/security settings, restart counts, and profile mount evidence.
3. Verify hard-bound `observations.sql`/`evaluate.py` SHAs and exact Stage 8B2A/8B2B script SHAs. Confirm B/C isolated and migration report bindings are identical across the evidence chain.
4. Run `dormant` first. Dormant acceptance must not depend on scraper/browser/listener facts because those are outside that target.
5. Close default-off browser/listener ownership and existing-flow-health facts through a separately reviewed, privacy-safe, checksum-bound metadata source. This package intentionally freezes default-off even if unbound fields are asserted.
6. Before active capture, add checksum-bound account-identity, browser/listener, window-aligned physical-frame, spool-limit, and recovery evidence. Raw journal rows must never substitute for physical frames; this package intentionally cannot accept active targets.
7. Run `5m`, then `30m`, `2h`, and `24h` only after each preceding report accepts. Keep account aliases separate and retain exact snapshot/window/image evidence.
8. Observe reconnect and restart recovery only under a later explicit authorization. Until then both facts remain null and active acceptance freezes.
9. Stop enablement on `FREEZE_ENABLEMENT`; preserve spool, journal, and reports; do not auto-rollback schema or perform provider actions.
10. Later provider-authorized UAT covers identical bursts, FIFO text, media/caption/reply/reaction classes, reconnect, restart, and account/chat isolation. This package performs none of those actions.
