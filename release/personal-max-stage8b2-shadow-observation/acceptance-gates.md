# Acceptance gates

Every report is bound to one exact target, one of `5m`, `30m`, `2h`, or `24h`, an exact zero/one/two-account scope, a PostgreSQL snapshot identity, actual runtime image evidence, and the accepted immutable image source revision. Database counts and journal growth rates are windowed. Gateway counters are explicitly process-lifetime facts and never presented as window deltas.

The owner launcher first snapshots the observer into a root-owned `0700` file and verifies its exact SHA before execution; direct root execution from the codexbot-writable package is rejected. The observer then hard-binds `observations.sql` and `evaluate.py` by path and SHA-256 before first use. `SHA256SUMS` remains package inventory evidence and is not the runtime trust root. The final report is revalidated in full after evaluation and before ownership/mode handoff.

Stage 8B2A and 8B2B evidence is embedded in the sanitized report and validated exactly: final script SHAs, isolated/backup bindings, PostgreSQL-container credential authority, root-only inspect/env modes, fixed URL route, verified network labels and alias, single runner network, stable container identity, credentials absent from output/arguments, immutable gateway image, eight migration names, accepted ledger-only migration, accepted non-empty Prisma drift without raw SQL, fresh backup, runner cleanup, production immutability, safety, cross-report SHA bindings, internal dormant network, zero ports/mounts/DB writes/capture/sender/browser/MAX/provider actions, and exact non-automatic rollback/Compose artifact SHAs. The same read-only database snapshot revalidates the current 54-entry migration ledger, all eight expected transport migrations, exact raw-journal CHECK definitions, and the append-only trigger/function contract.

Raw journal rows are durable observations, not an independently observed count of physical WebSocket frames. The current observer emits physical-frame count as `null` with `UNKNOWN_NO_WINDOW_ALIGNED_PHYSICAL_FRAME_SOURCE`. Active capture acceptance therefore remains frozen until a separately authorized, privacy-safe, window-aligned physical-frame source exists.

- `dormant`: gateway container/image/source/health are exact, the container predates the full window, current Compose/network/port/mount/user/restart/security settings match the hardened dormant release, HTTP health is `200`, readiness is `dormant-ready`, account scope is empty, bound migration evidence starts with zero raw rows, current scoped raw rows/capture/spool are zero, and sender/projection/provider contracts are inactive. Scraper, browser, profile, and listener evidence are deliberately outside this target and are not acceptance requirements.
- `default-off`: dormant gateway requirements plus exactly one accepted scraper image, running/healthy/no restart, the exact read-write `/app/user_data` volume mount once, one browser owner, one listener owner, healthy existing flow, zero scoped journal rows, zero capture, and empty spool.
- `one-account`: exactly one sanitized alias, positive windowed raw-journal rows and growth rate, positive semantic comparison count, zero loss/duplicates/wrong-account/critical regressions/route conflicts, bounded spool with trusted limit evidence, exact runtime images, single browser/listener ownership, and separately observed reconnect/restart recovery.
- `ab`: exactly two distinct sanitized aliases; each account has positive raw-journal rows and growth rate; all one-account safety gates apply; wrong-account, route conflicts, and accidental duplicate envelopes remain zero.

The root observer intentionally leaves browser/listener ownership, existing-flow health, physical-frame count, spool-limit provenance, reconnect recovery, and restart recovery unknown unless an exact authorized source can observe them. Because no cryptographically bound external-evidence collector is included in this package, `default-off`, `one-account`, and `ab` are explicitly non-accepting preparation targets even if those fields are hand-authored; they freeze on `*_external_evidence_binding_missing`. A later reviewed package must add exact source/report SHA bindings before those paths can accept. The evaluator never executes rollback.
