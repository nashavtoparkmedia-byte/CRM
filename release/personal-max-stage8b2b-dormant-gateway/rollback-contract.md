# Bounded rollback contract

Rollback is never automatic because an unexpected failure first requires evidence review. The separate checksum-bound script requires its canonical non-symlink package/script path and caller-supplied self SHA. It hard-binds both the source Compose digest and the sanitized failure helper digest, requires the installed `root:root:0600` runtime Compose file to match the source, and verifies the exact container image, Compose project/service labels, Stage/mode labels, zero mounts, zero ports, runtime user, restart policy, sole internal network, network labels, and sole network member before targeted `compose down`. After proving the container and network absent and production unchanged, it revalidates the exact runtime Compose path/owner/mode/digest, removes only that file, removes the now-empty canonical `root:root:0700` state directory with `rmdir`, and proves both paths absent. It records only a hash of dormant logs and sanitized verified-target metadata and removes no image, volume, production network, scraper, database, or profile and performs no prune.

Every post-binding failure preserves the original exit code, source line, phase, and classification in one no-clobber `root:codexbot:0640` report. Its observations are tri-state: the exact container, network, runtime Compose file, and state directory are reported as `UNKNOWN`, `ABSENT`, `PRESENT_OWNED`, or `PRESENT_MISMATCH`; no “removed” claim is inferred from an interrupted command. The handler only observes and hands off evidence: it never retries teardown or removes anything. Unknown, mismatched, or partial-start inventory fails closed; a separate evidence-reviewed recovery action is required rather than inventing resource ownership.
