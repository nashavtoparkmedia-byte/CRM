# Cleanup contract

Every disposable Docker object carries both `personal-max.stage=8b1i` and a unique `personal-max.run-id`. Names use the `personal-max-stage8b1i-<run-id>` prefix and are collision-checked before mutation.

The EXIT trap removes only containers, the internal network, and the PostgreSQL and spool volumes matching both exact labels for the current run. It removes only validated Stage 8B1I temporary paths. Every inventory/removal operation has a deadline of at most 60 seconds and the cleanup sequence has one 300-second global deadline. It never runs a global prune, generic image cleanup, Compose, or a production-label cleanup.

Success requires proven zero labelled containers, networks, volumes, and temporary files after cleanup. Inventory failure is reported as `unknown`, never converted to zero, and the first cleanup failure classification is preserved. Accepted gateway and scraper images remain by design after success or failure. A failure report records bounded remaining counts, a cleanup classification, pre-existing/acquired image facts, disk gates, and the original failure without including commands, SQL, raw stderr, credentials, logs, message content, or provider payloads. If primary diagnostics fail, its exact validated temporary report path is removed and an independent minimal fallback preserves the original exit and emits either sanitized JSON or `FAILURE_REPORT_UNAVAILABLE`.

The accepted failure report SHA-256 `0203c1287fc2415367e10852fb83bb8001f558f2484c8e6cafe14d86c7d3dd67` records zero current-run containers, networks, volumes, and temporary files, consistently with the later run's cleanup. Its zero count must not be reinterpreted as an inventory of the older path.

Before a new run is created, the next separately authorized checksum-bound probe applies the exact prior-residual contract. It requires exact path and run-ID binding, non-symlink directory metadata, `root:root:0700`, stable device/inode identity, no mountpoint, a completed no-reference process scan, zero Docker containers/networks/volumes carrying both old-run labels, the exact accepted report SHA and metadata, and unchanged production Git fingerprints. Any failed or unknown gate refuses removal. Only the exact literal prior path may be removed; wildcards, prune, generic Docker cleanup, and unrelated `/var/tmp` cleanup remain forbidden.

Failure-handoff for the observed silent terminal result is classified `B. FAILURE_HANDOFF_EVIDENCE_INSUFFICIENT`: source and offline fixtures prove the report existed and bound the exact migration gate failure, but do not prove the exact runtime point that suppressed the original terminal block. The hardened invariant is independent of that missing evidence. After diagnostics load, every nonzero exit must produce exactly one validated primary report summary, validated emergency report summary, or explicit `FAILURE_REPORT_UNAVAILABLE`; it uses a dedicated terminal descriptor with fallback, preserves original phase/classification/check ID/exit across cleanup, prevents trap recursion and duplicate handoff, and surfaces an already-moved valid report if a later renderer step fails. Failure-report hashing and terminal emission do not depend on the disposable temporary directory.
